# Changelog

All notable changes are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- Autopilot probation, groundwork only (docs/autopilot-probation.md, steps 2 to 4): a `lossless-v2` policy that lists two recoverable hooks (`hook_repeat_read`, `hook_quiet_commands`), a `probation` state in which an optimizer runs on about half of new sessions so the two halves can be compared, and the rules for entering, keeping and leaving it. A trial is judged by the existing session-level comparison (`experiment`): kept only if the whole range of the cost change is below zero, no outcome is measurably worse and each side has at least 20 sessions; rolled back on a measured loss. Nothing offers `lossless-v2` to a user yet, so no behaviour changes today. The state file now has a second view for readers that can split sessions at random (only the gateway), so a trial is never on for everyone.
- Corrected the registry: `hook_repeat_read` and `hook_quiet_commands` are recoverable (the code always said so; the registry and docs said lossless), and a test now keeps every optimizer's tier in the registry equal to the code's. Neither can join Autopilot until its probation step exists. `hook_quiet_commands` and `hook_large_output` are marked as having no shadow saving estimate (how much a flag or hint removes depends on the command), so Autopilot refuses to judge them from shadow evidence and the planner says why instead of showing a figure.
- Autopilot can now charge for text an optimizer adds, so text-adding techniques can join its list later. The technique registry records each technique's per-session and per-use token cost and whether its own saving estimate already subtracts it (B6, B7 and B8 declare about 68, 42 and 54 tokens per use); Autopilot subtracts the rest from the shadow saving before judging it, and refuses to promote anything that adds text without declaring numbers. A test checks each declared figure against the real message. `Policy.OverheadTokens` is gone (the registry replaces it). Nothing new is promoted yet. See [docs/autopilot-eligibility.md](docs/autopilot-eligibility.md).
- Autopilot checks the user's real setup before it promotes an optimizer, and at every check after. A hook rewrite that no probe has seen work for the user's agent would only run as shadow, so Autopilot holds it back as "not available in your setup" and says what to run (`/trove:setup` or `trove hooks verify`); a promotion is undone if the probe stops covering it (for example after a Claude Code update). The technique registry now records which hook capability each technique needs, and a test keeps that in step with what the hooks really rewrite. The probe record's types moved to `internal/hookcaps`; behavior elsewhere is unchanged. See [docs/autopilot-eligibility.md](docs/autopilot-eligibility.md).
- Autopilot now works for a user with no gateway. It reads the hooks' own shadow counts (`hook_events`) as well as the gateway's, counts hook sessions toward the baseline, takes the larger of the two channels' figures (never the sum, since both see the same waste), and holds back an optimizer that needs a channel the user is not using (for example the duplicate collapser without a gateway) as "not available in your setup". Before this, a subscription user could not have anything promoted. See [docs/autopilot-eligibility.md](docs/autopilot-eligibility.md).
- Spend cap, shadow mode only (`[optimizers] spend_cap = "shadow"`, off by default; needs a budget cap from `trove budget set`): for API-key traffic through the gateway, marks requests that arrive when spending in the budget period has already reached the cap and records on their rows what a hard cap would have stopped (an estimate). Nothing is refused or changed. The ledger is read at start, at period rollover and every five minutes, with the cost of each recorded request added in between, so a request never waits for the database. It shows in `trove report` and `trove optimize status`. `"on"` runs as shadow. See [docs/spend-cap.md](docs/spend-cap.md).
- In-flight dedup, shadow mode only (`[optimizers] inflight_dedup = "shadow"`, off by default): for API-key traffic through the gateway, counts requests that arrive while an identical one is still waiting for the provider and records on that request's row what making one call for both would have saved (an estimate). Nothing is shared or changed. It shows in `trove report` and `trove optimize status`, costs about 55 microseconds per request on a 217 KB body, and compares credentials only through an in-memory HMAC that is never stored or logged. `"on"` runs as shadow. See [docs/inflight-dedup.md](docs/inflight-dedup.md).
- Technique registry (`internal/technique`) and `trove techniques [check <name>...]` (listed by `trove advanced`): one list of every built, candidate and wrapped technique with where it acts, how it is obtained, whether it can change the cached prompt, which logins it works for, declared overhead, conflicts and licence, and one check for whether a set can run together. `trove external` takes its built-in overlap from it, and Autopilot holds an optimizer back, with the reason, when something already on cannot run beside it. See [docs/techniques.md](docs/techniques.md).
- `cache_ttl` suggestion (`trove report`, `trove optimize suggest`): from your own Claude Code history, says whether the other prompt cache lifetime (5 minutes or 1 hour) would have been at least 25% cheaper, separately for the main conversation and subagents, and names the setting to change. Silent unless the difference is clear (at least $1, from at least 100 requests). No dollar figure unless the history shows an API key. Advice only. See [docs/optimize.md](docs/optimize.md).
- `trove fix` check `settings_check` (ids `chk-`): proposes deleting a cost-raising setting you already have in your own Claude Code settings: prompt caching switched off, `ENABLE_TOOL_SEARCH=false`, or a one-hour cache lifetime (only when your history shows one-hour cache writes). A suggestion only, never in `--all`, no saving figure, one key removed with formatting kept, undo byte for byte.
- Settings catalog: `effortLevel`, `ENABLE_TOOL_SEARCH` and `MAX_MCP_OUTPUT_TOKENS` are now verified from raw documentation text (2026-11-13) and can be written; new verified entries `bashOutputMaxChars`, `autoCompactWindow`, `idleCompaction`, `promptCacheTtl`, `subagentPromptCacheTtl`, `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` and a display-only `BASH_MAX_OUTPUT_LENGTH`. No profile sets any of them yet. See [docs/settings.md](docs/settings.md) and [docs/techniques.md](docs/techniques.md).
- Autopilot (`trove autopilot [on|off|pause|resume]`, a consent step in `trove setup`): after one consent Trove starts the eligible lossless optimizers in shadow, promotes one only from shadow evidence at a session boundary, and rolls it back to shadow if a guardrail trips. Your own `config.toml` setting always wins. State is in `autopilot.json`. Thresholds are placeholders until a benchmark runs. See [docs/autopilot.md](docs/autopilot.md).
- Autopilot follow-ups: `trove receipts` and the status line name the optimizers that were on; `trove report` and `trove autopilot` show a 7-day summary (and `--json` an `autopilot` object); a once-only desktop notice when an optimizer is turned on or rolled back (needs `[notifications] desktop = true`); `/trove:setup` offers Autopilot and `/trove:status` shows it; and a shadow planner that writes advice for every optimizer and changes nothing.

### Changed
- `trove --help` now lists 8 commands. The rest still work and are listed by `trove advanced`.
- CLAUDE.md rule 6 allows opt-in by agreeing once to a named policy.
- `trove --version` replaces `trove version` (same output, same `--json`). `trove version` still works as a hidden alias for one release. The plugin launcher tries `--version` first and falls back to `version`, so it still accepts a `trove` on PATH from an earlier release at the pinned version.

## [0.2.2] - 2026-11-12

Published as a regular release, not a pre-release. The release checklist ([docs/release-checklist.md](docs/release-checklist.md)) still has open items, listed under "Known gaps in this release" below. The notes under 0.1.0 were written before the earlier 0.2.0 and 0.2.1 tags and are folded into this release.

### Added
- Data controls: `trove data export` (every table as CSV plus Trove's own files, never the backups; recovery store only with `--include-recovery`) and `trove data delete` (usage data; keeps what `trove undo` needs; prints the request that asks the sharing receiver to delete a contributed summary, and sends nothing). `trove uninstall --purge-data` now also removes the consent record.
- `docs/data.md`: every stored field, every field sent after opting in, and a marked design (not built) for any team edition, each with purpose and retention. A test fails if it drifts from the schema. `docs/privacy-law.md` (for lawyer review, sources dated), a verbatim-clauses update and lawyer/Anthropic question lists in `docs/compliance.md`.
- Tests in CI: canary strings never reach the database, the data folder or anything shared (`internal/privacy`); every table has a retention decision (`internal/store`); no banned word in our own names (`internal/naming`).
- `trove reconcile`: compare Trove's recorded total for a period with a provider invoice; a difference within 2% (adjustable) counts as a match.
- `trove feedback`: build a prefilled GitHub issue with diagnostics (versions, agent names, counts, error classes), shown in full before anything is opened.
- `trove doctor` warns when bundled prices were last verified more than 30 days ago.
- `scripts/pricingage --strict --max-age-days N`: release gate for price freshness.
- `scripts/checkclaims`: fails if a launch draft states a figure without a measured or estimated slot that cites a real source file.
- README rewrite and new docs: measurement method, supported agents, beta checklist, install verification, release checklist, launch drafts.
- Claude Code plugin (`plugin/trove`, marketplace in `.claude-plugin`): hooks, `/trove:report`, `/trove:status`, `/trove:setup`, `/trove:uninstall`, a first-run report, and a capability check after Claude Code updates. Works with every login type; nothing is enabled without approval. New `trove plugin start|status|status-line`. `trove hooks install` refuses to double-register when the plugin is enabled. See [docs/plugin.md](docs/plugin.md). No `/trove:handoff` yet.
- OpenCode plugin (`plugins/opencode`, TypeScript; not published): runs the optimizer engine inside OpenCode through `trove engine serve`, for both plugin APIs OpenCode ships (1.x and 2.x). Works with an API key or a GitHub Copilot login; ChatGPT and other subscription logins are shadow-only. Request-level transforms on 2.x for Anthropic bodies; tool-level on both. Engine protocol gains `hello` (version handshake), `session`, `observe`, a harness and login label, what-the-harness-cannot-do, and recording into the new `adapter_events` table; `trove report` shows a Harness plugins section. See [docs/opencode.md](docs/opencode.md). Not yet run on a real OpenCode.
- `trove bench stress`: a five-layer offline stress suite for the optimizer engine and the gateway (invariants, fuzzing, fault injection, load, realism), with a nightly workflow and [docs/stress.md](docs/stress.md). It runs against a fake upstream and makes no provider call. Its only HTTP client can dial loopback addresses only.
- `trove bench journeys`: an offline user-journey simulation with a calibration gate.
- `measure.NetGuard`: a rule that switches an optimizer off for later sessions when its net saving (tokens removed minus its declared overhead) is negative or its outcomes worsen, applied only at session boundaries.
- Prices re-verified on 2026-11-12 against the official pages (data version 2026-11-12.1). Added Claude Fable 5.2 and Mythos 5.2 (with fast mode), Gemini 4 Carbon and Hydrogen, and future-dated entries for Gemini 2.5 Pro and Flash, which are billed at newer models' rates from 2026-12-01.

### Changed
- **Behavior change: the gateway is opt-in through `trove setup --gateway`.** A plain `trove setup` no longer points Claude Code or Codex CLI at the gateway; it reports that the gateway is opt-in and changes no gateway setting. Subscription users are never pointed at it by default. `trove gateway stop` now puts back the gateway setting Trove changed (the previous value, or no value if there was none), the same as `trove undo` does for that setting. `trove doctor` warns with a "gateway address" check when `ANTHROPIC_BASE_URL` points at a local address where no gateway is running. **If you ran `trove setup` before this release,** run `trove doctor`. If it flags the gateway address, run `trove gateway stop` (or `trove undo` to reverse every change Trove made). Then run `trove setup --gateway` only if you want the gateway.
- `ANTHROPIC_API_KEY` must now be a Claude Console API key: `sk-ant-api...` or `sk-ant-usr-...`, at least 32 key characters after the prefix. OAuth tokens (`sk-ant-oat...`), admin keys and other values are refused by the gateway, `trove setup` and `trove hooks probe --live`, each with a plain-English reason. A key supplied through `apiKeyHelper` is not checked by setup.
- New `trove contribute delete`: asks the sharing receiver to delete everything stored under your install id (one `DELETE`, shown first and confirmed, no body, credentials or cookies, no redirects), then turns sharing off and removes the local id. It is the only thing that sends it. CLAUDE.md rule 1 gains part (c) to allow exactly this.
- `trove setup` no longer points Claude Code at the gateway unless there is evidence it will use an API key (`ANTHROPIC_API_KEY` set, an `apiKeyHelper`, a Console login, or `plan = "api_key"` in config.toml), so a Claude.ai login token is never sent to the gateway by setup. Codex CLI is unaffected.
- `trove data delete` keeps the hook state files (`hooks/config.json`, `hooks/capabilities.json`) so the hooks do not quietly revert to defaults.
- Retention now covers every table that holds history, not four of fifteen, and runs from the session-end hook and `trove report` as well as the gateway, so it no longer needs the gateway (closes finding F-8). Tables that are current state are kept and listed with the reason.
- The engine validates a request's JSON once (and the output once if an optimizer changed it) and forwards unchanged any body that is not valid JSON or nests deeper than 128 levels. The output trimmer remembers what it did for each text it has seen, so a resent history costs a lookup, not a rescan.
- Recovery: a stored output whose bytes no longer hash to its ID is discarded and reported as unavailable, never returned as the tool's output.
- Prices: `o4-mini` is removed because it is no longer on OpenAI's pricing page and cannot be verified (it now comes back unpriced). Gemini 3.5 Flash-Lite batch cache reads are $0.015, not $0.02, and its flex requests are unpriced because flex cache reads differ from batch.
- The egress allowlist gains `internal/stress/loopback.go` and the QA-only `qa/loadtest`; both can only dial loopback addresses. PRIVACY.md, the threat model and the compliance notes say so.
- Internal renames for the naming rule: `internal/logs/claudecode` is `cchistory`, `internal/logs/codex` is `cxhistory`, and the benchmark agent module is `trovebench.agent.cc`. No user-visible command, config key or route changed.

### Known gaps in this release
- Install, uninstall, Homebrew and `install.sh` have not been verified by hand on clean macOS or Linux machines ([docs/install-verification.md](docs/install-verification.md) is still blank). Automated tests run on Windows locally and on Linux in CI.
- The Claude Code plugin has not been run end to end on a real login on macOS or Linux, and the OpenCode plugin has not been run on a real OpenCode.
- `cosign verify-blob` has not been run against the published release, and the Homebrew formula has not been installed from the tap. The install script and the npm wrapper check the SHA-256 only, not the signature.
- The compliance, legal and agent-integration documents were last re-checked on 2026-11-06 and were not re-checked for this release.
- Prices were compared with the official pages on 2026-11-12. OpenAI's own policy pages cannot be read by automated tools.
- No benchmark run has been completed, so no savings claims are made. Codex CLI history parsing has not been verified on a real install.

## [0.1.0] - not yet released

The stable release will include everything above and below. Nothing below was published on its own.

### Added
- Local gateway (opt-in, `127.0.0.1`) for API-key use with Claude Code and Codex CLI; `trove setup` and `trove undo` with backups.
- Request analysis: token estimates, cache-miss reasons, waste detectors, shadow savings.
- Optimizers (all off by default, shadow mode first, automatic rollback by guardrails): `noise_normalizer`, `duplicate_result_collapser`, `cache_breakpoints`, `volatile_prefix_mover`, `output_trimmer`; suggestions for model choice, Batch API and reasoning effort.
- Measurement, reports, budgets, receipts, status line and share card.
- History audit: reads Claude Code and Codex CLI session history without the gateway, and detects API-key or subscription plans without reading credentials.
- `trove fix`: `mcp_prune`, `context_slim`, `cache_breaker_fix`, `model_default`, with exact diffs and per-fix undo.
- MCP server (`trove_read`, `trove_search`, `trove_run`, `trove_fetch_full`) with a path jail and a local recovery store.
- Agent hooks (repeat-read prevention, session receipts) and `trove hooks`.
- `trove uninstall` with byte-exact restore and optional data purge.
- Pricing engine with verified, dated price data and `trove pricing show`.
- Security work: key-leakage and no-egress tests, threat model, privacy statement, compliance checklist and findings report.
- Reproducible builds; cosign-signed checksums and SBOMs; Homebrew, npm and install-script distribution.

### Known gaps
- No benchmark run has been completed, so no savings claims are made.
- Real-agent verification checklists are still pending for most features; see [docs/supported-agents.md](docs/supported-agents.md).
- Codex CLI history parsing has not been verified on a real install.
- macOS and Linux have not yet been tested by hand; automated tests so far ran on Windows and in CI.
