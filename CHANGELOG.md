## [Unreleased]

### Added
- Learned verbosity level (`trove optimize verbosity [--days N] [--apply [--force]]`): picks `optimize.verbosity` for `verbosity_steer` from recorded sessions. It picks `terse` when at least 15% of long replies (200+ output tokens) were cut short, meaning the client closed the stream or a user message followed within 15 s of the reply ending. A user turn is told apart from a tool turn because it adds no tool-result tokens. Otherwise it picks `concise`. The level is chosen only with at least 10 sessions and 50 long replies. Every run is a dry run first that shows the chosen level, its evidence and the thresholds, labeled estimated. `--apply` writes the line marked as learned, for new sessions only. A level the user set by hand is never replaced without `--force`. Metadata only. No new table or column (plan item 6.5).
- Rule-set trials (`trove autopilot trial <terse-rules|ponytail|caveman> [--yes] [--stop]`, T2, one explicit yes per trial): a per-user A/B in which the SessionStart hook gives an installed, switched-off rule set's text to a random half of new Claude Code sessions as `additionalContext` (again after a resume, `/clear` or compaction; arm pinned per session; hook contract verified on code.claude.com on 2026-11-17). At each session boundary Autopilot reads the comparison and records a verdict with output tokens per turn, cost per turn, test-fail rate per arm and turns, each labeled measured. The test_fail_rate guardrail or a worse result stops the trial; Autopilot never turns a rule set on. Every hook trial's comparison now also reports output tokens per turn, cost per turn (sessions whose every request was priced) and test-fail rate per arm. No new table (plan item 6.6).
- Gateway verbosity steering (`verbosity_steer`, technique B20, T2, off by default): one fixed note asking for shorter replies, appended after the last byte of the system prompt of Anthropic Messages requests, so every byte the agent sent and its cache markers stay put and each turn stays the previous one's prefix (a 30-turn test checks each system form). `optimize.verbosity` = `concise` (default) or `terse`, pinned per session. Each request is charged the note's tokens (at most about 85, estimated). It holds the brevity-rules slot: an external rule set (`terse-rules`, `ponytail`, `caveman`) cannot be enabled beside it, and a session that starts with one on gets no note. New optimizer tier `behavior`. Anthropic caching order verified on platform.claude.com on 2026-11-17; OpenAI requests are untouched. No new table (plan item 6.4).
- Caveman as a T2 external rule set (`trove external install|enable|remove caveman`, technique W4, now wrapped): the Apache-2.0 skill text `skills/caveman/SKILL.md`, pinned at tag v4.1.0 and verified raw on github.com/JuliusBrussee/caveman on 2026-11-17, added to `~/.claude/CLAUDE.md` as one fenced block with a diff, a backup and an exact undo, charged for its whole text per request. Frontmatter and the alias and status paragraph are removed and the block's first line says so; its LICENSE and NOTICE ship in the binary. Its proxy, CLI, Auto mode and login are never installed. A Caveman block added by hand tags the session `brevity_rules`. No new table (plan item 6.2).
- `terse-rules`, `ponytail` and `caveman` stay in the one `behavior_rules` slot: a test enables every pair in both orders and expects a conflict naming the rule set already on (plan item 6.3).
- Ponytail as a T2 external rule set (`trove external install|enable|remove ponytail`, technique W9): its MIT-licensed `AGENTS.md` rules text, pinned at tag v5.3.3 and verified raw on github.com/DietrichGebert/ponytail on 2026-11-17, added to `~/.claude/CLAUDE.md` as one fenced block with a `<!-- trove:managed -->` line, a diff, a backup and an exact undo. Only one output-style rule set (`terse-rules`, `ponytail`) can be on at a time. Every rules block is now charged for its whole text, fences and marker included (terse-rules 104 -> 156 tokens per request, estimated). A Ponytail block added by hand tags the session `brevity_rules`. No new table (plan item 6.1).
- Cursor and Gemini CLI hooks: `trove hooks install --agent cursor|gemini` (user level; `trove hooks uninstall` and `trove undo` remove only Trove's entries) adds repeat-read prevention, edit records, session reset and the session-end receipt to `~/.cursor/hooks.json` or `~/.gemini/settings.json`; `--rewrite` adds the shell pre-hook (both) and the output hook (Gemini CLI only; Cursor replaces output for MCP tools only). A thin translation layer maps each agent's hook input and replies (`internal/hooks/agents.go`); rewrites stay in shadow until a live or session probe records that the agent honours them, and rewrites the adapter cannot express are never counted. `trove logs scan` now reads Gemini CLI session history (`~/.gemini/tmp/<project>/chats/*.jsonl`, priced as Google, plan unknown); Cursor history is not read because its format is undocumented. Hook contracts verified on cursor.com and geminicli.com on 2026-11-17; nothing has run on a real install yet. No new table (plan item 5.6, blocked on the live probe).
- Quiet-command error-visibility check: a quiet rule can name a recorded failing run (`ErrorFixture`), and a test fails unless the quiet output keeps every failure line of the default output. `pytest -q` passes on a recorded pytest 9.1.1 run; cargo has no recording and stays shadow. No new table (plan item 5.7).

- `output_trimmer` now trims application logs too: plain-text logs with level words, logfmt, HTTP access lines and JSON-lines logs. It keeps every line reporting an error, warning, failure, exception, panic or fatal (with its context and stack trace), every outlier line (template seen at most twice once numbers and ids are masked), every line over 4,000 bytes, and the first and last lines. Pretty-printed JSON documents are left alone. The per-optimizer checker now also plays `incident-log-forensics` and a new `json-log-triage` workflow, counts JSON `"level":"error"` records as failure lines, and fails if any trim marker names an output the recovery store does not hold byte for byte. Scripted savings with every optimizer on (estimated): `json-log-triage` 42.8%, `debug-with-logs` 8.9%, `incident-log-forensics` 3.2% (was 2.5%; its repeated stack traces are all kept). No new table (plan item 5.3).
- MCP snippet with consent (`mcp_snippet`, `snip-` ids, a T2 behavioural suggestion, never in `--all`): when Trove's MCP server is registered, `trove fix` offers to append the `trove mcp snippet` text to the project's `CLAUDE.md` with a diff and `trove undo`. No saving is claimed; its overhead (about 70 tokens per request, estimated) is charged and declared in the technique registry (B19). Once applied, `trove fix` shows the share of file reads and searches that used Trove's tools before and after it (estimated, from session history, all projects) and the per-session overhead at the project's measured requests per session (`mcp_snippet_use` in JSON). No new table (plan item 5.5).
- Retyped commands as `trove_run` commands (`retyped_command`, `run-` ids, a T1 suggestion, never in `--all`): `trove fix` finds a shell command the agent typed out at least `fixer.retyped_min_count` (default 5) times in at least `fixer.retyped_min_sessions` (default 3) sessions of the project's Claude Code history, grouped by hash, and offers to add it to `.trove/commands.toml` with a diff and `trove undo`. Commands that need a shell become a manual step, because `trove_run` never runs one, and `trove mcp trust` must still approve the file. Adoption is measured by the existing `adopted` counter and shown by `trove fix` (`trove_run_adoption` in JSON). Command text is read in memory only. Bash `tool_input.command` verified on code.claude.com/docs/en/hooks on 2026-11-17. No new table (plan item 5.4).
- Outline-first large reads (`hook_read_outline`, off by default, T1 recoverable): a `Read` without offset or limit that returns 40 KB or more of a source file the outliner knows is replaced by the file's outline and line ranges, with the full text in the recovery store for `trove_fetch_full`; a second full `Read` goes through whole. It stays in shadow until `trove hooks probe` sees `Read` honour `updatedToolOutput`, and the `hook_extra_read` guardrail rolls it back when the agent keeps reading outlined files whole (plan 5.2).
- Hook output dedup (`hook_output_dedup`, off by default, T1 recoverable): after a Bash, Grep or Glob call, an output byte-identical to one earlier in the session is replaced by a one-line pointer, with the full text in the recovery store for `trove_fetch_full`. No time-based expiry; compaction forgets it. Needs the Trove MCP server and recovery store, otherwise it stays shadow. Fetch-backs are counted and judged by the existing `hook_fetch_back` guardrail. Only hashes go in the per-session ledger file; no new table (plan item 5.1).
- In-flight dedup decision: sharing duplicate in-flight requests is not built; it stays shadow only unless its estimate exceeds 1% of gateway spend (docs/decisions/inflight-dedup.md). The `inflight_dedup` row in `trove report` now states that share (`spend_share_pct` in JSON, estimated) and which side of the 1% bar it is on. No new table (plan item 4.4).
- Keep-warm pings for API-key gateway traffic (`keep_warm`, off by default): in `on` mode, about 4.5 minutes after a cached Claude request the gateway resends it with `max_tokens: 0` (the provider's documented pre-warm request) and the same key, so the 5-minute cache is still there when the session continues. At most `gateway.keep_warm_max_pings` (default 2, at most 6) per idle session and `gateway.keep_warm_daily_cap_usd` (default and maximum $1) per day; pinging stops when, over 24 hours, the pings cost more than they are estimated to have saved. Requests with a 1-hour cache marker, extended thinking, structured outputs or a forced tool choice are never pinged. Each ping is its own billed usage row (agent `keep_warm`). `shadow` holds nothing and records, on the session's next request, what pings would have saved or cost (estimated). The key and last request body are held in memory only while pings are pending (CLAUDE.md rules 1(d), 2 and 7; approved in docs/decisions/keep-warm.md). Provider rules verified on platform.claude.com on 2026-11-17. Checked live on 2026-11-17 (claude-haiku-5-5): after two pings across a 10.5-minute gap the next request read the whole 3,723-token prefix and wrote none; a ping with adaptive thinking was accepted. No new table (plan item 4.3).
- `cache_breakpoints` can now set a cache lifetime for each marker it adds for custom agents: `[optimize.cache_ttl]` takes `tools`, `system` and `messages`, each `"5m"` (default, same bytes as before) or `"1h"`. A longer lifetime must come before a shorter one; config validation and the optimizer both refuse other orders (the request is then forwarded untouched). The lifetimes are pinned per session, so the cached prefix stays byte-stable. Ordering rule verified on platform.claude.com prompt-caching docs on 2026-11-17. No new table; `session_pins` gains a `cache_ttl` column (JSON of `"5m"`/`"1h"` per marker, NULL for the default) so a gateway restart keeps the session's lifetimes (plan item 4.2).
- `trove fix` can now apply the cache lifetime suggestion: new `cache_ttl_main` (`ttl-`) and `cache_ttl_subagents` (`ttlsub-`) fixes set `promptCacheTtl` or `subagentPromptCacheTtl` to `"5m"` or `"1h"` in `~/.claude/settings.json`, with a diff and `trove undo`, under the same thresholds as the suggestion (at least 100 requests, 25% and $1 cheaper). They are suggestions, never part of `--all`, and become advice when the project sets the key. `trove report` checks afterwards that the history's cache writes moved to the new lifetime (`cache_lifetime` in JSON, measured with enough sessions on each side), and `settings_check` no longer offers to delete a lifetime one of these fixes set. No new table (plan item 4.1).
- `context_slim` now deletes only provable duplicates: a section is removed only when every line also appears in the README, `docs/` or an earlier section of the same file (it used to accept 70%), and each deleted line is shown beside the matching source line as evidence. Removing generic overview or boilerplate sections moved to a new `context_slim_generic` fix (`ctxg-`), a T2 behavioural suggestion that is never part of `--all`. No new table (plan item 3.4).
- The tool-search fix (`ENABLE_TOOL_SEARCH=false`) now suggests the per-server alternative: set `"alwaysLoad": true` on the one server whose tools must always be present, so every other server stays deferred. Verified on code.claude.com/docs/en/mcp ("Exempt a server from deferral") on 2026-11-17. No new table (plan item 3.3).
- Every fix that removes text sent with each request (MCP pruning, the tool-search check, context slimming, changing lines) now shows the tokens it re-sends on every request and the requests per session they are multiplied by, in `trove fix <id>` and as `resent_tokens_per_request`, `resent_label`, `requests_per_session` and `requests_label` in JSON. MCP tool-definition tokens are measured per server from gateway requests (apportioned from provider-reported totals; the analyzer now records `tool_servers` in each request's estimates). File text stays estimated. Requests per session are measured from the project's Claude Code history, so subscription users get them too. Gateway rows recorded before this change carry no per-server figure, so MCP numbers appear after new gateway traffic. No new table (plan item 3.2).
- Per-optimizer CI checker: every shipped optimizer now runs alone over scripted sessions with failure output, and CI fails unless it keeps every failure line, keeps the cached prefix byte-identical and repeats byte for byte (`internal/stress/checker.go`, see `docs/stress.md`). The workflow report's failure-line count now also accepts a line kept with its colors, so optimizers other than the noise normalizer are no longer counted as dropping it. No new table (plan item 2.5).
- Turn-inflation guardrail: every optimizer verdict now states its extra turns per session against the reference (measured) and what they cost in tokens per session (estimated, at the on sessions' tokens per turn), in the summary and as `extra_turns` in JSON, whatever the verdict. A new `turn_inflation` rule rolls an optimizer back to shadow when its sessions take more turns than the reference by more than `measure.retry_increase_percent` (default 30%) beyond chance. Turns count for every session, including ones without readable tool signals. No new table (plan item 2.4).
- Per-session outcomes in reports: settings-profile effects now also compare the last allowlisted test status (share of sessions whose last test run failed) and git commits per session, next to tool errors, turns and abandoned sessions, and say which of them had too few sessions. "No regression detected" in `trove report`, and each guardrail summary, now name exactly the signals that had enough sessions to be checked; with none, the report says no check has run yet instead of claiming no regression. Guardrail rules gain a `signal` field in JSON; settings outcomes gain `lower_is_worse`. No new table (plan item 2.3).
- `test_fail_rate` guardrail: Autopilot rolls a trial back to shadow when sessions with the optimizer on end with failing tests (last allowlisted test run, measured) more often than sessions without it. It needs at least 10 such sessions per arm, and the gap must be over 10 points (5 for T3 routing techniques); these numbers are placeholders until a benchmark sets them. The bench ship rule takes an optional `tier`, and T3 studies use a success (test-pass) margin of at most 2 points. No new table (plan item 2.2).
- Test-pass signal: a new `post_tool_test_result` hook (Claude Code `PostToolUse` and `PostToolUseFailure` on Bash, installed by `trove hooks install` and the plugin) records the exit code of commands that exactly match a test command in the project's `.trove/commands.toml`, stored as a hashed command id and the code in the new `test_runs` table (never the command, its output or the folder). The session roll-up (`sessions.outcome_signals`) gains `tests`: last status (pass, fail or none), runs and failures. Run `trove hooks install` again to add the hook. Checked live on Claude Code 2.1.326: a passing run arrives as `PostToolUse` (exit 0) and a failing one as `PostToolUseFailure` with `Exit code N` (plan item 2.1).
- Plugin-only and subscription users now get real numbers in `trove status-line` and `trove report`. With no gateway traffic in the period, the status line reads your agent's session logs and shows usage as API-equivalent value (estimated, never "spend" and no budget pace), the current session's share of that usage, and the measured A/B verdicts (the best optimizer's change in cost per session and how many cost more). `trove report` adds `savings_share_percent` (estimated savings as a share of usage) to its headline. API-key history still counts as spend. New JSON fields: `basis`, `api_equivalent_usd`, `ab_verdict`, `session.share_of_usage_percent`. No new table (plan item 1.7).
- Hook token estimates now use bytes per token learned from your own session logs, per model family, instead of the fixed 3.5. `trove hooks sync` (and the session-end hook) learn the ratio from consecutive requests in your history where the cache stayed warm, over the last 30 days, and only use a family's ratio after 20 clean pairs; the ratio is pinned when a session starts. Each estimate in the hook spool records the ratio and its sample size. Figures stay labelled estimated, and with too little history the default 3.5 is used. No new table (plan item 1.6).
- Benchmark priors are now checked when loaded: every prior must name its source (`bench:`, `contribute:` or `team:`) and have a self-consistent range, or the file is rejected. A prior can no longer hide a loss: if your own cost range is wholly above zero, the combined range shows your numbers unchanged. The shipped priors file is still empty until a real study runs (plan item 1.4, blocked on bench results).
- The A/B report (`trove report`, and its JSON as `cost_per_turn` and `cost_per_uncached_input_token`) now shows cost per turn and cost per uncached input token, each measured with a seeded 95% range, ahead of cost per session. Sessions with no turns or no uncached tokens are left out of that figure, not counted as zero. The rollback verdict still uses cost per session.
- The A/B cost figures are adjusted for each session's prior cost (CUPED, method pre-registered in `docs/benchmark-methodology.md` section 4a), which narrows their ranges on the same sessions. It is used only when prior cost predicts cost; the report and JSON (`adjusted`, `covariate`, `unadjusted_value`, `unadjusted_low`, `unadjusted_high`) always show the unadjusted figure too. Outcome metrics are not adjusted.
- A confounder tag is recorded when a session starts (a known brevity rule block, a skills listing, or an enabled third-party tool; names only, never text). `trove report` and its JSON (`confounders`) note every A/B comparison that mixes sessions with and without one, since part of the difference may come from that rather than the optimizer. New nullable column `session_pins.confounders`.
- Scout and cascade (tier T3) now get a session-level A/B: while one is installed, new sessions are randomly assigned an arm by the hooks, a new `pre_tool_subagent` hook declines the scout in the off arm, and `trove report` compares the arms on tokens, turns and tool errors from your agent's history. Cascade's off arm is recorded but cannot be blocked.
- Every technique in the registry has a class and a tier (T1 safe, T2 behavioural, T3 routing), and a test fails if one has none or if a T2 or T3 technique is marked for Autopilot without a benchmark verdict. The registry's old `tier` field (lossless, recoverable, behavior) is now `effect` in `trove techniques --json`; `tier` now holds T1, T2 or T3.
- `trove optimize suggest` and `trove fix` show each suggestion's tier and an evidence label (`estimated` when it has a saving figure, else `unmeasured`), in text and JSON (`tier`, `class`, `evidence_label`). The Batch API suggestion is T1.
- `install.ps1`: a one-line installer for Windows (`irm https://raw.githubusercontent.com/usetrove/trove/main/install.ps1 | iex`). It checks the release's SHA-256 checksums (and the cosign signature when cosign is installed), refuses to install on a mismatch, installs `trove.exe` for the current user, and adds its folder to the user `PATH` so `trove` works at once (opt out with `TROVE_NO_PATH=1`; it changes nothing else). `install_test.ps1` tests it against a fake local release in CI, on Windows PowerShell 5.1 and PowerShell 7.
- `trove bench workflows`: replays ten hand-scripted Claude Code sessions through the real optimizer engine, offline (no API call, no spend), in three tiers: everyday sessions, output-heavy sessions, and the everyday sessions again as a custom agent that sends no cache markers. It reports estimated savings per tier, and measured checks that nothing was lost (every failure line still visible to the model, trimmed output recoverable byte for byte, cached prefix byte-identical, repeat runs identical) and engine time per request. `--analyze` adds the oracle ceiling, output-size and trimmer-threshold what-ifs, and a modelled re-read diff. See [docs/workflows.md](docs/workflows.md) and `bench/scripts/95_workflows.sh`.
- Benchmark scripts: `90_final_study.sh` (a larger two-condition study on the tasks already prepared), `91_optimizer_activity.sh` (what the optimizers actually removed in a study), `92_long_tasks_study.sh`, `93_labelled_numbers.sh`, `94_other_levers.sh`, and `power_check.py` (how many pairs the ship rule needs, estimated from a finished batch).

### Changed
- Codex hook rewrites now need a live or session probe, like every other agent: Codex documents `updatedInput` only together with `permissionDecision: "allow"`, which Trove never sends, so its documentation no longer counts as evidence. Codex documents no field that replaces tool output, so Codex output rewriting is not built (learn.chatgpt.com/docs/hooks, re-read 2026-11-17; plan item 5.7, blocked on the Codex live probe).
- Fixed overhead now comes first. `trove fix` lists MCP pruning, the tool-search check and context slimming ahead of other fixes, `trove report` lists unused tool definitions and heavy context files ahead of other leaks, and `/trove:setup` offers those fixes before anything else. They need no gateway and work on subscriptions. Both `--json` outputs mark them with `fixed_overhead`. The share card still names the largest leak.
- Shadow estimates for the hooks no longer count output the agent would have cut anyway: Bash output past 30,000 characters, and MCP results and file reads past 25,000 tokens. The limits, the Claude Code version the docs described and the date they were read are in the settings catalog (`output_cap`). Trove does not read your own override of a limit, so a raised limit only makes an estimate lower. All such figures stay labelled estimated.
- Automatic rollbacks (the retries, tool-error and re-fetch guardrails, the hook guardrails, and a third-party tool's net cost) now use sequential, always-valid tests. The chance of a false rollback stays at most 5% however often the check runs, where checking every few minutes and at every session end used to drive it far higher. The price is that a rollback needs more evidence: at a 25% limit, 11 of 20 actions instead of 5, and a rate sitting exactly at the limit no longer trips it. See `docs/measurement.md`, "Sequential rollback checks".
- The repository now carries only the user-facing and test-required docs. Internal process notes (verification and release checklists, legal and research notes, launch drafts) are no longer tracked; they remain in the history and in earlier releases. Issue and pull request templates were added.
- `output_trimmer` now recognizes BuildKit (`docker build`) logs as build output. It still keeps failures and stack traces and stores the full output.
- The benchmark verdict (`stats.compare`) resamples whole tasks, so repeats of one task cannot make an interval look tighter than the data allows. With one run per task the results are identical to before.

### Known gaps
- The scripted-session savings are estimates from sessions written by hand; how often a file is re-read or how noisy a shell is are assumptions, not measurements of real users.
- The SWE-bench study `swebench-gateway-2` (35 tasks, NEED MORE DATA) ran on a separate machine and its result files are not yet committed.

## [0.4.0] - 2026-11-14

### Added
- Autopilot trial policy `lossless-v3`: the two v2 candidates plus `output_trimmer`, `hook_large_output` and `hook_read_limit`, tried one at a time in that order. It needs its own yes: `trove autopilot trials on` shows what is added and asks again, and a user who agreed to v2 keeps exactly v2 until then (what v2 already kept stays). The consent text is generated from the policy, so it cannot list fewer changes than the policy makes. The numbers (20 sessions per side, 28 days) are the same unvalidated placeholders. See [docs/autopilot-eligibility.md](docs/autopilot-eligibility.md).
- Guardrails that set a trial candidate back to shadow by themselves: `hook_read_limit` (a limited read followed by a read of more of the file; limit twice the shared rate) and `hook_large_output` (fewer than 10 percent of the sessions where the `trove_run` hint was given then used `trove_run`). A new hook `post_tool_run` counts use of `trove_run`; installs from v0.3.0 or earlier need `trove hooks install` again, `trove hooks status` says so, and until then that guardrail does not run rather than guess. New event kinds `extra_read` and `adopted` (migration 0018); both appear in `trove report` and `trove hooks status`. See [docs/hooks.md](docs/hooks.md).
- Security: `docs/security.md` (every control, what it does not protect against, and the test for each), an updated threat model and findings, a fuller `SECURITY.md` with how to verify a release, Dependabot, CodeQL and `go mod verify` in CI, and `install.sh` verifies the cosign signature when cosign is present (`TROVE_REQUIRE_SIGNATURE=1` refuses unverified installs).
- Supply chain: SLSA build provenance on release archives (`gh attestation verify`), a licence-free secret scan over tracked files (`scripts/secretscan`), and a CI job that builds one commit from two directories and compares the bytes (`scripts/rebuild-check.sh`). None has run in CI yet.

### Changed
- `output_trimmer` now declares its overhead (its marker is netted inside its estimate; the 351 tokens of Trove MCP tool definitions are charged per session, kept equal to the real schema by a test), so Autopilot can trial it. It is trialled through the hooks only, so a subscription user can trial it too, and its guardrail is now half as tolerant as the shared rate (12 percent instead of 25) because it hides text.
- The gateway has a whole-request read timeout (5 minutes; a response stream is not limited) and caps the request bodies it holds in memory at once (1 GiB in total; one over the budget gets a plain 503 the agent retries; a lone request is never refused for its size). Free-text redaction now also covers AWS, GitHub, Google, Slack, Stripe and npm keys and PEM private keys. A symlinked agent settings file is written through, so the link stays. `trove_run` drops more credential-looking environment names.
- Corrected stale text: probation is built (the docs said it was not), and the planner now covers every trial candidate, with each tier read from the technique registry.

### Known gaps
- All Autopilot thresholds and trial numbers (including the 50%, 12% and 10% limits) are unvalidated placeholders. `output_trimmer` and `hook_large_output` have no study arm; their trials on your own sessions are their only evidence.
- Left open on purpose in the security review: the recovery store holds raw output (F-9), port squatting on a shared machine (F-13), `trove_run` filters its environment by name pattern (F-28), the npm wrapper checks the checksum only (F-15).
- SLSA provenance and the rebuild check are new and unproven on a release; the first tagged release is their first real run.
- Installs from v0.3.0 or earlier need `trove hooks install --rewrite` again to get the `trove_run` counter.

## [0.3.0] - 2026-11-14

### Added
- Benchmark: each trial candidate hook can now be measured by itself (`alone_hook_repeat_read`, `alone_hook_quiet_commands`, `alone_hook_read_limit`: the hook on, no gateway, everything else off), with a study template (`bench/studies/hooks-single-1.yaml.template`) and `bench/tools/hook_activity.py`, which reports in how many runs a hook actually acted so that a "no clear difference" result can be read correctly. No study has been run; Autopilot's trial thresholds remain placeholders until one is.
- `trove autopilot trials on|off`: a second, separate yes that lets Autopilot try two changes that are not lossless (`hook_repeat_read`, `hook_quiet_commands`). Each is first watched in shadow, then runs one at a time for about half of new sessions, chosen at random, and is kept only if the comparison is clean (fewer tokens, no more turns or tool errors, at least 20 sessions on each side, dropped after 28 days with no clear result; these numbers are unvalidated placeholders). It never runs if A/B comparison is off, never beside a setting you made, and for a user with no gateway never if history reading is off. `trove setup`, `--yes` and `--autopilot` do not give this consent, `trials off` withdraws it and removes anything a trial kept, and `trove autopilot` and `/trove:status` show what is on trial and how far along it is. See [docs/autopilot-probation.md](docs/autopilot-probation.md). Not yet run on a real install.
- Autopilot probation now works for a user with no gateway (docs/autopilot-probation.md, steps 6 and 7). While a hook technique is on trial the hooks give each new session a random side (on or shadow) from a hash of its key and record it; the comparison counts tokens per session, turns and tool errors for every assigned session from the gateway's record or, when there is none, the agent's own local history, which Trove reads at session end for at most 700 ms and only while a trial runs. A new shared reader (`internal/histscan`) makes that read identical to `trove logs scan`. Also fixes a plan error: the gateway cannot split sessions for hook-only techniques, so those trials no longer wait for gateway traffic. Still nothing offers `lossless-v2` to a user, so nothing changes today.
- Autopilot probation, groundwork only (docs/autopilot-probation.md, steps 2 to 4): a `lossless-v2` policy that lists two recoverable hooks (`hook_repeat_read`, `hook_quiet_commands`), a `probation` state in which an optimizer runs on about half of new sessions so the two halves can be compared, and the rules for entering, keeping and leaving it. A trial is judged by the existing session-level comparison (`experiment`): kept only if the whole range of the cost change is below zero, no outcome is measurably worse and each side has at least 20 sessions; rolled back on a measured loss. Nothing offers `lossless-v2` to a user yet, so no behaviour changes today. The state file now has a second view for readers that can split sessions at random (only the gateway), so a trial is never on for everyone.
- Corrected the registry: `hook_repeat_read` and `hook_quiet_commands` are recoverable (the code always said so; the registry and docs said lossless), and a test now keeps every optimizer's tier in the registry equal to the code's. Neither can join Autopilot until its probation step exists. `hook_quiet_commands` and `hook_large_output` are marked as having no shadow saving estimate (how much a flag or hint removes depends on the command), so Autopilot refuses to judge them from shadow evidence and the planner says why instead of showing a figure.
- Autopilot can now charge for text an optimizer adds, so text-adding techniques can join its list later. The technique registry records each technique's per-session and per-use token cost and whether its own saving estimate already subtracts it (B6, B7 and B8 declare about 68, 42 and 54 tokens per use); Autopilot subtracts the rest from the shadow saving before judging it, and refuses to promote anything that adds text without declaring numbers. A test checks each declared figure against the real message. `Policy.OverheadTokens` is gone (the registry replaces it). Nothing new is promoted yet. See [docs/autopilot-eligibility.md](docs/autopilot-eligibility.md).
- Autopilot checks the user's real setup before it promotes an optimizer, and at every check after. A hook rewrite that no probe has seen work for the user's agent would only run as shadow, so Autopilot holds it back as "not available in your setup" and says what to run (`/trove:setup` or `trove hooks verify`); a promotion is undone if the probe stops covering it (for example after a Claude Code update). The technique registry now records which hook capability each technique needs, and a test keeps that in step with what the hooks really rewrite. The probe record's types moved to `internal/hookcaps`; behavior elsewhere is unchanged. See [docs/autopilot-eligibility.md](docs/autopilot-eligibility.md).
- Autopilot now works for a user with no gateway. It reads the hooks' own shadow counts (`hook_events`) as well as the gateway's, counts hook sessions toward the baseline, takes the larger of the two channels' figures (never the sum, since both see the same waste), and holds back an optimizer that needs a channel the user is not using (for example the duplicate collapser without a gateway) as "not available in your setup". Before this, a subscription user could not have anything promoted. See [docs/autopilot-eligibility.md](docs/autopilot-eligibility.md).
- Spend cap, shadow mode only (`[optimizers] spend_cap = "shadow"`, off by default; needs a budget cap from `trove budget set`): for API-key traffic through the gateway, marks requests that arrive when spending in the budget period has already reached the cap and records on their rows what a hard cap would have stopped (an estimate). Nothing is refused or changed. The ledger is read at start, at period rollover and every five minutes, with the cost of each recorded request added in between, so a request never waits for the database. It shows in `trove report` and `trove optimize status`. `"on"` runs as shadow. See [docs/spend-cap.md](docs/spend-cap.md).
- In-flight dedup, shadow mode only (`[optimizers] inflight_dedup = "shadow"`, off by default): for API-key traffic through the gateway, counts requests that arrive while an identical one is still waiting for the provider and records on that request's row what making one call for both would have saved (an estimate). Nothing is shared or changed. It shows in `trove report` and `trove optimize status`, costs about 55 microseconds per request on a 217 KB body, and compares credentials only through an in-memory HMAC that is never stored or logged. `"on"` runs as shadow. See [docs/inflight-dedup.md](docs/inflight-dedup.md).
- Technique registry (`internal/technique`) and `trove techniques [check <name>...]` (listed by `trove advanced`): one list of every built, candidate and wrapped technique with where it acts, how it is obtained, whether it can change the cached prompt, which logins it works for, declared overhead, conflicts and licence, and one check for whether a set can run together. `trove external` takes its built-in overlap from it, and Autopilot holds an optimizer back, with the reason, when something already on cannot run beside it. See [docs/techniques.md](docs/techniques.md).
- `cache_ttl` suggestion (`trove report`, `trove optimize suggest`): from your own Claude Code history, says whether the other prompt cache lifetime (5 minutes or 1 hour) would have been at least 25% cheaper, separately for the main conversation and subagents, and names the setting to change. Silent unless the difference is clear (at least $1, from at least 100 requests). No dollar figure unless the history shows an API key. Advice only. See [docs/optimize.md](docs/optimize.md).
- `trove fix` check `settings_check` (ids `chk-`): proposes deleting a cost-raising setting you already have in your own Claude Code settings: prompt caching switched off, `ENABLE_TOOL_SEARCH=false`, or a one-hour cache lifetime (only when your history shows one-hour cache writes). A suggestion only, never in `--all`, no saving figure, one key removed with formatting kept, undo byte for byte.
- Settings catalog: `effortLevel`, `ENABLE_TOOL_SEARCH` and `MAX_MCP_OUTPUT_TOKENS` are now verified from raw documentation text (2026-11-13) and can be written; new verified entries `bashOutputMaxChars`, `autoCompactWindow`, `idleCompaction`, `promptCacheTtl`, `subagentPromptCacheTtl`, `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` and a display-only `BASH_MAX_OUTPUT_LENGTH`. No profile sets any of them yet. See [docs/settings.md](docs/settings.md) and [docs/techniques.md](docs/techniques.md).
- Autopilot (`trove autopilot [on|off|pause|resume]`, a consent step in `trove setup`): after one consent Trove starts the eligible lossless optimizers in shadow, promotes one only from shadow evidence at a session boundary, and rolls it back to shadow if a guardrail trips. Your own `config.toml` setting always wins. State is in `autopilot.json`. Thresholds are placeholders until a benchmark runs. See [docs/autopilot.md](docs/autopilot.md).
- Autopilot follow-ups: `trove receipts` and the status line name the optimizers that were on; `trove report` and `trove autopilot` show a 7-day summary (and `--json` an `autopilot` object); a once-only desktop notice when an optimizer is turned on or rolled back (needs `[notifications] desktop = true`); `/trove:setup` offers Autopilot and `/trove:status` shows it; and a shadow planner that writes advice for every optimizer and changes nothing.

### Changed
- **Behavior change: the gateway is opt-in through `trove setup --gateway`.** A plain `trove setup` no longer points Claude Code or Codex CLI at the gateway; it reports that the gateway is opt-in and changes no gateway setting. Subscription users are never pointed at it by default. `trove gateway stop` now puts back the gateway setting Trove changed (the previous value, or no value if there was none), the same as `trove undo` does for that setting. `trove doctor` warns with a "gateway address" check when `ANTHROPIC_BASE_URL` points at a local address where no gateway is running. **If you ran `trove setup` before this release,** run `trove doctor`. If it flags the gateway address, run `trove gateway stop` (or `trove undo` to reverse every change Trove made). Then run `trove setup --gateway` only if you want the gateway.
- `ANTHROPIC_API_KEY` must now be a Claude Console API key: `sk-ant-api...` or `sk-ant-usr-...`, at least 32 key characters after the prefix. OAuth tokens (`sk-ant-oat...`), admin keys and other values are refused by the gateway, `trove setup` and `trove hooks probe --live`, each with a plain-English reason. A key supplied through `apiKeyHelper` is not checked by setup.
- New `trove contribute delete`: asks the sharing receiver to delete everything stored under your install id (one `DELETE`, shown first and confirmed, no body, credentials or cookies, no redirects), then turns sharing off and removes the local id. It is the only thing that sends it. CLAUDE.md rule 1 gains part (c) to allow exactly this.
- `trove setup` no longer points Claude Code at the gateway unless there is evidence it will use an API key (`ANTHROPIC_API_KEY` set, an `apiKeyHelper`, a Console login, or `plan = "api_key"` in config.toml), so a Claude.ai login token is never sent to the gateway by setup. Codex CLI is unaffected.
- `trove data delete` keeps the hook state files (`hooks/config.json`, `hooks/capabilities.json`) so the hooks do not quietly revert to defaults.
- Retention now covers every table that holds history, not four of fifteen, and runs from the session-end hook and `trove report` as well as the gateway, so it no longer needs the gateway (closes finding F-8). Tables that are current state are kept and listed with the reason.
- The engine validates a request's JSON once (and the output once if an optimizer changed it) and forwards unchanged any body that is not valid JSON or nests deeper than 128 levels. The output trimmer remembers what it did for each text it has seen, so a resent history costs a lookup, not a rescan.
- Recovery: a stored output whose bytes no longer hash to its ID is discarded and reported as unavailable, never returned as the tool's output.
- Prices: `o4-mini` is removed because it is no longer on OpenAI's pricing page and cannot be verified (it now comes back unpriced). Gemini 3.5 Flash-Lite batch cache reads are $0.015, not $0.02, and its flex requests are unpriced because flex cache reads differ from batch.
- The egress allowlist gains `internal/stress/loopback.go` and the QA-only `qa/loadtest`; both can only dial loopback addresses. PRIVACY.md, the threat model and the compliance notes say so.
- Internal renames for the naming rule: `internal/logs/claudecode` is `cchistory`, `internal/logs/codex` is `cxhistory`, and the benchmark agent module is `trovebench.agent.cc`. No user-visible command, config key or route changed.
