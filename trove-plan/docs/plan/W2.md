# W2. Quality signals (v0.6), a prerequisite for T2 and T3

## 2.1 [M]
Change: Add a test-pass signal. A PostToolUse Bash handler records only the exit status of commands that match the project's allowlisted test command, stored as an exit code plus a hashed command id
Where: Hooks, `trove_run` allowlist, `scripts/hookprobe`, `docs/hook-capabilities.json`
Done when: The live probe confirms the Bash PostToolUse payload, and the signal shows up in the session rollup

## 2.2 [M]
Change: Add a `test_fail_rate` guardrail. Feed it into Autopilot rollback and the bench ship rule. T3 uses a stricter threshold than T2
Where: `internal/measure`, `internal/autopilot/advance.go`
Done when: A trial is rolled back when its sessions end with failing tests more often than the reference arm

## 2.3 [S]
Change: Add per-session outcomes: last test status (pass, fail or none), git commit count, turn count and abandoned sessions. These extend the tool-error, turns and abandoned counts that SettingsEffects already uses (PR #6)
Where: Session rollup, `internal/report`
Done when: "No regression detected" names the exact signals that were checked

## 2.4 [S]
Change: Add a turn-inflation guardrail. A lever that adds turns has the cost of those turns counted against it, since thinner context can mean more turns: RTK added 13.8% more turns in JetBrains' test, and Headroom needed 237 turns versus 180 in tokbench
Where: `internal/measure`
Done when: Extra turns appear in every verdict

## 2.5 [S]
Change: Run a CI checker for each optimizer: failure lines kept, prefix byte-identical, repeat run identical
Where: `internal/stress`, CI
Done when: No transform merges without a passing checker
